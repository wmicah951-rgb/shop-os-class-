# Governance note · Shop-OS Estimate Agent

**Accountable person:** Micah [last name], project owner and the only person who deploys, configures and holds the keys for this agent.

**What data it reads and stores, and where.** The agent reads four things through read-only tools: Shop-OS work orders (ticket, vehicle, symptoms, status), parts inventory, technicians, and shop rates. By default these come from a snapshot bundled with the code; in live mode the server makes GET-only calls to the Shop-OS demo API at shop21-zeta.vercel.app. Customer names, emails and phone numbers are removed before any data reaches a tool result, so the model never sees them. Visitors can also open up to three sandbox work orders per chat by typing a vehicle and a suspected issue (max 80 and 500 characters); that text lives only in their signed chat token and is sent to the model like any chat message. The Clients, Vehicles, Calendar, Schedule and Reports pages of Shop-OS are deliberately locked in the public demo because they hold customer personal data or business numbers. Each message and its tool results are sent to the model provider (DeepSeek API, model deepseek-chat) to produce a reply. Nothing is stored on the server: the conversation lives in the visitor's browser tab as a signed token and disappears on reload or "New chat." Approved drafts go into that same token, a sandbox, and never into the Shop-OS database. Vercel keeps its standard request logs. The model key and Shop-OS credentials live only in Vercel environment variables, never in the page, the repo or a recording.

**Where the human gate sits.** The one action that changes anything is `save_draft_estimate`. The gate sits between the model's decision to call that tool and the tool actually running: the loop stops as soon as the model emits the call. The chat then shows a yellow "Approval needed: save_draft_estimate" card with the exact JSON arguments (ticket, labor hours, technician, part IDs and quantities), a note that the price is recalculated from shop data, and Approve / Reject buttons. The message box is locked until the person chooses. Reject sends "rejected, nothing was saved" back to the model.

**What a stranger with the link can and cannot do.** They can chat, look up demo work orders, parts, stock and technicians, get priced estimates, and approve drafts into their own sandbox session. Caps apply: 12 messages per chat, 10 tool calls and 12 model calls per message, 1,200 output tokens per answer, 800 characters per message. They cannot write, edit or delete real Shop-OS data (the agent only has GET access), see customer contact details, send emails or texts, take payments, change prices or give discounts (the tool recomputes every price, including on save), or forge chat history or tool results (the state token is HMAC-signed on the server). They can still try prompt injection to change the agent's wording or pull it off topic, and heavy use could exhaust the free-tier model quota. The DeepSeek account is prepaid with a small balance and no auto-recharge, so the worst case is the agent going offline when the credit runs out, not an open-ended bill. This breaks the "lethal trifecta": the agent reads untrusted input but holds no private customer data and has no outbound channel to send data anywhere.
